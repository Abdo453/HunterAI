## 1. القواعد الحاكمة (Definition of Done لكل مرحلة)

1. **لا `CONFIRMED` بلا إثبات:** كل مسار يكتب حالة تأكيد يمرّ إما بـ`EvidenceCourt` بإثبات قابل لإعادة التقييم (`ProofStrength.DERIVED`)، أو بمُعلَن مُوسَّم عبر بوابة موثوقة موثّقة (`DECLARED` + `allow_declared_proof`).
2. **حوكمة إلزامية:** كل عملية حسّاسة (تنفيذ أداة/أمر/شبكة) تمرّ `Scope Engine` + `Policy Gate` بنمط **fail-closed**.
3. **قابلية التدقيق:** كل تنفيذ يسجّل: `project_id` · `tool_id` · `action` · `timestamp` · قرار التصريح · النتيجة/الحالة.
4. **لا أسرار** في المصدر أو التهيئة أو artifacts التفقيق (تنقيح عند المخارج).
5. **التوافق الخلفي:** لا تغيير لواجهة عامة/CLI بلا سبب موثّق + توافق.
6. **إيقاع المرحلة:** اختبارات موجّهة خضراء → فحص صحة → مراجعة `git diff` → شرح + رسالة التزام مقترحة → **توقّف للاعتماد**.
7. **قياس لا سرد:** عند أي "بيئي/متوقّع"، أعد القياس مباشرة قبل الاستنتاج (§8.1 من التدقيق).

## 6. إيقاع التنفيذ والتحقق

لكل مرحلة: (1) فرع/تغيير معزول → (2) تنفيذ → (3) اختبارات موجّهة + بصلة كاملة عند الحاجة → (4) فحص صحة → (5) مراجعة diff → (6) رسالة التزام → (7) **توقّف للاعتماد**.

**ملاحظة بيئية:** المستودع يُلتزَم تلقائيًا في هذه البيئة (commits أثناء العمل)؛ لذا تُقدَّم الرسائل المقترحة للتوثيق، وتُراجَع حالة `git` قبل كل مرحلة لتفادي خلط العمل.
